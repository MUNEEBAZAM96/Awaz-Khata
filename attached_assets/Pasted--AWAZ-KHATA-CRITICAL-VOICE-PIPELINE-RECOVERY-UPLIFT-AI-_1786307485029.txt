# AWAZ KHATA — CRITICAL VOICE PIPELINE RECOVERY + UPLIFT AI SDK CORRECT IMPLEMENTATION

You are working on the existing **Awaz Khata (آواز کھاتہ)** application.

This is a **production-critical debugging and recovery task**.

The application previously had a working voice transaction pipeline. After recent changes, the voice feature has regressed and users are seeing errors such as:

> "Unable to listen"

Speech is not being reliably converted into text, and as a consequence transactions are not being correctly extracted or stored.

Your job is to **find the root cause, repair the entire voice pipeline, and verify it end-to-end**.

Do NOT treat this as a UI redesign.

# 4. UPLIFT STT IMPLEMENTATION REQUIREMENT

For audio received from Expo, the backend will normally receive the audio as binary data.

Convert/obtain the uploaded audio as a Node.js `Buffer`.

Then call Uplift approximately like:

```typescript
const { transcript } = await client.stt.transcribe({
  file: audioBuffer,
  fileName: originalFileName,
  model: "scribe",
  language: selectedLanguage,
});
```

IMPORTANT:

When using a `Buffer`, Uplift requires:

```text
fileName
```

for format detection.

Therefore:

```typescript
file: audioBuffer
fileName: "recording.m4a"
```

must be provided correctly.

DO NOT omit `fileName`.

# 12. UPLIFT CLIENT CONFIGURATION

Use the SDK's retry and timeout support appropriately.

The official SDK supports:

```typescript

  apiKey,
  maxRetries: 3,
  timeout: 60000,
});
```

The SDK automatically retries transient errors such as:

```text
408
429
500
502
503
504
```

Do not implement a second aggressive retry loop around the SDK that could cause duplicate requests.

A reasonable configuration for voice transcription is:

```text

timeout: 60000
```

Choose based on the existing application's requirements.

# 13. HANDLE UPLIFT TYPED ERRORS

The official SDK provides:

```typescript
UpliftAIError
UpliftAIAuthError
UpliftAIInsufficientBalanceError
UpliftAIRateLimitError
```

Use these error classes where appropriate.

For example:

```typescript
try {
  const result = await client.stt.transcribe(...);
} catch (err) {
  if (err instanceof UpliftAIAuthError) {
    // invalid API key
  } else if (err instanceof UpliftAIRateLimitError) {
    // rate limited
  } else if (err instanceof UpliftAIInsufficientBalanceError) {
    // insufficient balance
  } else if (err instanceof UpliftAIError) {
    // other Uplift error
  }
}
```

Every Uplift error contains a request ID.

Use it in server-side diagnostics:

```text
requestId
statusCode
code
```

but NEVER expose secrets.
