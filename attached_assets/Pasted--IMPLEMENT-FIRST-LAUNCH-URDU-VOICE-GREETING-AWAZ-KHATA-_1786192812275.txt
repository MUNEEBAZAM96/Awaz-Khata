# IMPLEMENT FIRST-LAUNCH URDU VOICE GREETING — AWAZ KHATA

Implement a **first-time welcome voice experience** for Awaz Khata.

The goal is to make the very first launch feel like the user is meeting a personal Urdu financial assistant.

This is NOT a normal splash screen.

It should feel like:

> **The app is speaking directly to the user for the first time.**

---

# 1. FIRST-LAUNCH BEHAVIOR

When the user opens Awaz Khata for the first time:

```text
App opens
   ↓
Welcome screen
   ↓
Animated microphone / voice orb
   ↓
Generate Urdu greeting using existing /api/speak
   ↓
Play greeting using existing audio playback system
   ↓
Greeting finishes
   ↓
Smooth transition to Home
```

The greeting should only automatically play **once per installation/local app state**.

Do not play it every time the user opens the app.

---

# 2. GREETING TEXT

Use this Urdu greeting:

> السلام علیکم! آواز کھاتہ میں خوش آمدید۔ میں آپ کا ذاتی مالی معاون ہوں۔ آپ مجھ سے اپنے پیسوں کے بارے میں بات کر سکتے ہیں۔

The greeting should sound natural when spoken by Uplift AI.

Do NOT make the sentence unnecessarily long.

The purpose is simply to introduce:

* the app
* the voice interaction
* the financial-assistant concept

# 7. AUDIO STATE

Create a small state machine:

```text
welcome-loading
welcome-speaking
welcome-finished
welcome-error
```

### welcome-loading

Show:

```text
تیار ہو رہا ہوں...
```

while `/api/speak` is being called.

### welcome-speaking

Show:

```text
آپ سے بات کر رہا ہوں...
```

while the audio is playing.

### welcome-finished

Transition to Home.

### welcome-error

Do NOT block the user from using the app.

If TTS fails:

```text
السلام علیکم! 👋

آواز کھاتہ میں خوش آمدید۔

چلیں، آپ کا حساب شروع کرتے ہیں۔
```

Then show:

```text
شروع کریں
```

and allow the user to enter the Home screen.

---

# 8. USE THE EXISTING SPEAK API

Do NOT call Uplift AI directly from the frontend.

Use the existing API service.

The flow must be:

```text
Frontend
   ↓
POST /api/speak
   ↓
Backend
   ↓
Uplift AI TTS
   ↓
Backend returns audio
   ↓
Frontend
   ↓
Expo audio playback
```

Reuse the existing `api.js` service.

If a `speak()` method already exists, reuse it.

Do not create duplicate API logic.

---

# 9. AUDIO PLAYBACK

Reuse the existing audio playback implementation.

Do not create a second unrelated audio system.

The playback lifecycle should be:

```text
request TTS
   ↓
receive audio
   ↓
create Sound
   ↓
play
   ↓
monitor playback
   ↓
when finished:
    unload sound
    update state
    transition Home
```

Make sure audio resources are properly unloaded.

Avoid memory leaks.

---

# 10. IMPORTANT — AUTOPLAY ROBUSTNESS

The greeting should attempt to play automatically on first launch.

However, mobile platforms can sometimes restrict or interfere with autoplay behavior.

Implement graceful handling.

If playback cannot start automatically:

Show:

```text
السلام علیکم 👋

آواز کھاتہ میں خوش آمدید۔

▶️ تعارف سنیں
```

The user can tap the button to start playback.

Do NOT leave the user stuck on the welcome screen.

---

# 11. SKIP BUTTON

Add a small secondary option:

```text
بعد میں
```

or:

```text
Skip
```

Prefer Urdu:

```text
بعد میں
```

If the user taps it:

* stop any current audio
* unload the sound
* mark the welcome experience as completed
* navigate to Home

The skip button should NOT visually compete with the main experience.

It can be a small text button near the bottom.

---

# 12. LOCAL FIRST-LAUNCH FLAG

Use local device storage to remember whether the greeting has already been completed.

Use an Expo-compatible storage solution already present in the project.

If no storage solution exists, use:

```text
@react-native-async-storage/async-storage
```

if compatible with the project's Expo SDK.

Use a key such as:

```text
awaz_khata_welcome_completed
```

Possible value:

```text
"true"
```

Flow:

```text
App launch
   ↓
Check local flag
   ↓
false / missing
   ↓
Show welcome
   ↓
Greeting finishes
   ↓
Set flag true
   ↓
Home
```

If:

```text
true
```

then skip the welcome experience completely.

---

The first-launch greeting flag is purely UI/onboarding state.

Do NOT store it in the backend.

Do NOT create an API endpoint for it.

Do NOT modify the financial transaction model.

Do NOT involve the database.

# 18. AUDIO COMPLETION

When the audio finishes:

1. Update state to `welcome-finished`.
2. Mark welcome as completed.
3. Unload the audio.
4. Wait approximately 200–300ms if necessary.
5. Navigate to Home.
6. Home should start in `idle`.
7. Do NOT automatically start the microphone.

The user should arrive at Home ready to interact.

---

# 19. ERROR HANDLING

If `/api/speak` fails:

Do NOT display:

```text
AxiosError
Network Error
500 Internal Server Error
```

Instead show:

```text
معذرت، آواز ابھی دستیاب نہیں۔

آپ ابھی بھی ایپ استعمال کر سکتے ہیں۔
```

Then provide:

```text
شروع کریں
```

The app must remain usable.

---

# 20. PREVENT DUPLICATE PLAYBACK

This is important.

React components can mount more than once during development or navigation.

Make sure the greeting does NOT play twice.

Use appropriate guards/ref/state.

For example, conceptually:

```text
hasStartedRef
```

or an equivalent mechanism.

The greeting should only trigger once during that welcome session.

---

# 21. HANDLE APP BACKGROUNDING

If the user backgrounds the app while the greeting is playing:

Handle the audio lifecycle gracefully.

Do not create multiple Sound instances.

If the audio is interrupted:

* clean up
* allow the user to continue
* do not crash
* do not restart repeatedly
